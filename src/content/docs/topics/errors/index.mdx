# JMeter Error Playbooks

A grounded, symptom-based directory of dedicated playbooks for every error, exception, and bottleneck encountered when running Apache JMeter.

Each playbook follows an identical structure:
1. **Symptom & Exact Signature** - Real stack traces and messages from `jmeter.log`, View Results Tree, and JTL outputs.
2. **Quick Diagnosis (TL;DR)** - Direct 2-sentence summary for immediate triage.
3. **Common Causes** - Root cause breakdown explaining underlying network, JVM, or protocol behavior.
4. **Ordered Fixes** - Practical, copy-pasteable configuration snippets, CLI commands, and properties.
5. **Interactive Tools & Related Guides** - Direct bridges to calculators, cheat sheets, and manual sections.

:::tip[Standard Triage Protocol]
Before running large-scale tests, always debug with **1 thread and 1 loop** in GUI mode with **View Results Tree** enabled. Once the script succeeds cleanly, disable all visual listeners and run in CLI mode ([best practices](/user-manual/best-practices/)).
:::

## Interactive Diagnostic Tools

Use these interactive web tools on docs.jmeter.ai alongside the error playbooks:

- [Heap & Memory Estimator](/tools/heap-estimator/) - Calculate optimal `-Xms`, `-Xmx`, and Metaspace parameters based on thread counts.
- [Thread & Throughput Calculator](/tools/thread-calculator/) - Apply Little's Law to calculate target concurrency from desired RPS and response time.
- [CLI Command Builder](/tools/cli-builder/) - Generate production-ready non-GUI command lines with logging and property flags.
- [Regex Extractor Builder](/tools/regex-tester/) - Validate regular expressions against response data without starting JMeter.
- [Properties Cheat Sheet](/tools/properties-cheatsheet/) - Searchable catalog of all `jmeter.properties` and `user.properties`.
